# WHAT_IF — data-loss / corruption scenario matrix

Context: a customer's DSQL tables went to 0 rows (`refund_event`) or far below the DMS/source
counts over a weekend on old (pre-Oct-1) scripts. The root cause can no longer be confirmed.
The only code that can empty a whole target table is the **load** job's empty-and-reload
(`blank_whole_table` / `blank_whole_table_composite`, invoked by `assert_empty_or_register`
under `AUTO_REBLANK_ON_RESUME`). **CDC** deletes row-by-row: by PK (`apply_file`), by full-row
content match for no-PK tables, and a `_cdc_file` purge for no-PK file replay (`apply_file_nonpk`).

This matrix is "whatever the cause, the pipeline must **refuse, or stop and flag**, instead of
losing data, and a loss must be detected within one poll cycle." Each row names today's behaviour
(file:line as of HEAD `5e4adf8`), the risk, the guardrail added, and the covering test.

Line numbers are **pre-change** (HEAD `5e4adf8`). `cont` = `scripts/glue_cdc_continuous.py`,
`comp` = `scripts/glue_cdc_composite.py`, `load` = `scripts/job2_load.py`,
`val` = `scripts/job3_validate.py`.

## Guardrail → scenario coverage

- **G1** no destructive op once CDC started → #2, #20
- **G2** destructive blank only from a RUNNING workflow execution OR a manual run with `--allow_manual_destructive=true` (manual loads/validates may always write; CDC never gated) → #1, #20
- **G3** per-table lock (load fail-closed, CDC skip+warn) → #3, #4, #5, #20
- **G4** blank sanity (prior-attempt + count vs expected×margin) → #6, #7
- **G5** audit_log before every destructive op → #6, #C, and the incident attribution
- **G6** CDC mass-delete guard (fraction + absolute, per file & per cycle) → #8, #14
- **G7** no-PK delete precision + exact `_cdc_file` purge → #9, #10
- **G8** ordering / high-water / gap / new-LOAD-after-CDC → #11–#15, #B
- **G9** drift detector (counters + periodic compare + metric + optional block) → #5, #13, #16, #17
- **G10** validate & cutover vs DMS `FullLoadRows (+I−D)` → #18, #19

All guards default **SAFE** (refuse / stop & flag). Every override is an explicit, documented
setting, SQL flag, or run-input flag (row #23).
